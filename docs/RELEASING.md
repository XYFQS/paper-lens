# 发布文献透镜到 GitHub

本指南面向项目维护者。普通用户只需从 Releases 下载 `.xpi`，它就是 Zotero 插件安装包。

## 1. 准备源码与安装包

在 VS Code 中提交并推送本次准备发布的源码和文档，确认 GitHub 仓库显示的是这些改动。当前仓库为 [XYFQS/paper-lens](https://github.com/XYFQS/paper-lens)。

在项目根目录运行打包命令（需要 Windows PowerShell，无需额外下载打包软件）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
```

当前版本会生成：

| 文件                               | 用途                        |
| ---------------------------------- | --------------------------- |
| `dist/paper-lens-2.0.1.xpi`        | 用户直接安装的插件包        |
| `dist/paper-lens-2.0.1-source.zip` | 完整源码与文档              |
| `dist/SHA256SUMS.txt`              | 两个压缩包的 SHA-256 校验值 |

文件名里的版本号取自 `addon/manifest.json`，改完版本号后表格这两行要同步更新。`dist/` 被 Git 忽略，因此 VS Code 同步源码不会上传安装包。这三个文件应作为 Release 附件上传。

打包脚本会先删除 `dist/` 中此前的 `paper-lens-*.xpi` 和 `*.zip`，避免误传旧版本。

## 2. 创建 Release

1. 打开仓库的 **Releases**，点击 **Draft a new release**（首次可能显示 **Create a new release**）。
2. 在 **Choose a tag** 中创建 `v2.0.1`，**Target** 选择刚推送源码所在的分支。仓库早期标签 `V1.0.0` 用的是大写，从 `v1.0.1` 起改用小写 `v`，后续保持小写。
3. 标题填写 `文献透镜 Paper Lens v2.0.1`，填写下方发布说明。
4. 将 `dist/` 中上述三个文件拖入附件上传区，等待上传完成。
5. 正式版不勾选 **This is a pre-release**；检查内容后点击 **Publish release**。需要暂存时选 **Save draft**。

步骤依据 [GitHub 官方 Release 管理指南](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)。

可直接使用的发布说明：

```markdown
文献透镜 2.0.1，支持 Windows / Zotero 9.0.6。相对 1.0.2 是一次大版本更新：关键词从三类扩展为六类，新增文献身份证、记忆句、人工校正和十二个检索维度。

新增

- 六类中英关键词：主题、区域、对象、方法、数据、变量，每类最多 5 个，中文和英文成对生成。信息不足时该类为空，不猜测、不凑数。
- 主要结论：只从标题、摘要或明确的元数据中提取，最多 3 条，同时参与搜索。
- 文献身份证：在搜索页直接显示当前选中论文的完整画像——记忆句、研究画像、主要结论和文献管理字段，不必再展开“所选论文的研究关键词”逐条对照中英文。
- 记忆句：自动生成“作者 年份 | 期刊 | 区域 | 方法 | 结论”形式的一句话摘要，缺少的字段自动省略；可以手动改写，也可以一键恢复自动生成，不会额外调用 AI。
- 阅读进度与用途：阅读状态、重要程度、在论文中的用途，完全由你设置，AI 不会判断哪篇是核心文献、适合 Discussion 还是属于 Introduction。
- 人工校正：停用不准确的 AI 关键词，或补充自己的中英配对。停用后 AI 重新生成也不会再出现，自己添加的词不会被覆盖，AI 的原始结果始终保留。
- 十二个检索维度：条目类型、六类关键词、年份、期刊、阅读进度、重要程度、用途，支持“包含 / 不包含”，并可组合“全部满足 / 任一满足”。1.0.2 只有条目类型和三类关键词，共四个字段。
- 会议论文和书籍章节的期刊名（proceedingsTitle / bookTitle）同样参与记忆句和期刊检索。

变化

- 顶部页面由“找文献 / 准备文库 / 设置”改为“找文献 / 文库 / 设置”，“准备文库”并入“文库”。
- 文献身份证默认是一张只有文字的信息卡片：日常视图里没有输入框、没有删除按钮、也没有维护动作，点右上角“编辑”才展开控件，点“完成”收起，切换到另一篇论文自动回到卡片。信息顺序固定为论文基本信息 → 记忆句 → 研究画像 → 主要结论 → 文献管理。
- 原生标签由中英双语（研究区域：中国 / Study region: China）改为英文规范前缀 T:: R:: O:: M:: D:: V::，只保留一套命名；旧的“研究区域：中国”式标签会自动替换，人工创建的同名标签不会被删除，也不会被插件占用。
- 发送给 AI 的内容改为白名单字段，明确不发送附件、笔记正文、分类和本地路径。
- 新增“待更新”状态灯，提示哪些文献的条目信息已变化、建议重新生成画像。

修复

- 修复在主列表单击论文时文献身份证不跟随：单击或键盘上下键切换现在都会立即更新，不需要打开阅读器，也不需要手动刷新；从阅读器返回文库时同样跟随文库当前选择。
- 修复主要结论的英文被挤成一两个字母一行：英文现在与中文一样占满整行宽度。
- 修复折叠 Zotero 原生条目栏时文献透镜被一起隐藏：两个面板现在完全独立，各自的按钮只控制自己。这是相对 1.0.2 的行为变化——1.0.1 / 1.0.2 曾让插件面板跟随原生侧栏一起隐藏和恢复。

升级

从 1.0.2 升级不需要任何手动操作。首次读取文献信息时，插件会自动把旧索引升级为新结构，并在同一目录写入 index-v1-backup.json 备份。原有的研究区域、研究对象、研究方法关键词会保留并标记为“旧版关键词”，主题、数据、变量三类为空，建议重新生成一次画像补齐；文献信息、标签归属记录和人工标签都会保留。

安装：下载 paper-lens-2.0.1.xpi，在 Zotero 中选择“工具 → 插件 → 齿轮 → 从文件安装插件”。无需解压，从 1.x 升级直接安装即可。

不读取 PDF 全文，不推测论文结果，不移动文献，不管理文献分类；生成画像需自备 API Key，可能产生服务商费用。
当前版本需手动下载安装更新。
```

## 3. 发布后检查

在 Release 的 **Assets** 中确认能下载 `.xpi`。GitHub 自动附带的 **Source code (zip)** 和 **Source code (tar.gz)** 是标签对应的仓库源码，不能直接安装到 Zotero，见 [GitHub 关于 Release 的说明](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)。

下载一次上传的 `.xpi`，确认安装后版本正确，并用一个已有 1.x 索引的文库确认首次读取时会生成 `index-v1-backup.json` 且关键词保留。向用户分享 [Releases 页面](https://github.com/XYFQS/paper-lens/releases) 即可。

## 后续版本

更新 `addon/manifest.json` 和 `package.json` 的版本号，在 `CHANGELOG.md` 增加对应条目，完成测试、提交推送、重新打包，再创建对应标签及 Release，例如 `2.0.2` / `v2.0.2`。已经发布过的版本号不再复用。

当前 `manifest.json` 的 `update_url` 是占位地址，发布 Release 不会自动启用 Zotero 插件更新。自动更新需要另行配置更新清单和真实地址；配置前继续使用手动安装新版 `.xpi` 的方式。
